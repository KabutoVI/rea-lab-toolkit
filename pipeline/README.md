# pipeline

Local-model labeling pipeline for REA-Lab targets. See docs/LAB-CONVENTIONS.md for the
rules this supports (rule 3: local model summaries are an index, not
evidence, and must pass the checks documented here before being accepted).

## Checks a label must pass to be accepted

Every line written to a target's `summaries.jsonl` carries a `check`
field: `verified`, `unverified`, `failed`, or `skipped`. These are
mechanical checks run by `labeler.py`, not a judgment about whether the
label is actually correct, they only establish whether the label is
backed by something real in the source.

1. **Schema validation.** The model's response must be valid JSON
   matching the required schema (see `prompts/labeler_v1.txt` for the
   field definitions) via Ollama's structured-output `format` parameter.
   If the response is invalid JSON, or Ollama fails to respond, the
   script retries once with the same input. If it still fails, the line
   is written with `check: "failed"` and the raw bad output logged
   separately for debugging.

2. **Verbatim evidence check.** The model's `evidence` field must be an
   exact quote from the method source it was given, after normalizing
   whitespace on both sides (collapsing runs of whitespace, trimming
   leading/trailing whitespace) so formatting differences alone don't
   fail the check. It must also be at least 20 characters long and
   contain at least one identifier-like token (so a trivial or
   non-specific quote doesn't pass). If any of that fails, the label is
   still recorded but with `check: "unverified"`, it is not thrown away,
   just marked as not evidence-backed.

A label is only usable as a lead (per rule 3 in docs/LAB-CONVENTIONS.md) when `check` is
`verified`. `unverified` and `failed` labels stay in `summaries.jsonl` for
visibility (including on the dashboard) but must not be treated as
pointing at anything real without manual confirmation.

`skipped` means the method was never sent to the model at all (see
`too_long` below) - there is no label to check.

## Fields the script fills in itself, not the model

`function` and `exported_file` are filled in by the script from
`functions\manifest.json`, not generated by the model - the model is
never asked to identify which function it was given, since it already
knows this from the manifest, and asking it to repeat the name back is
just another thing that could be wrong.

`calls` is filtered after the model responds: any entry that is not a
literal substring of the method's source text is dropped before writing
the line, since the model is asked to only list calls that appear in the
source, but it can still hallucinate.

## too_long handling

Before calling the model, the script checks the method source length
against a character threshold (6000 chars, see `labeler.py`). This fits
comfortably within `num_ctx=8192` for both qwen3:14b and gpt-oss:20b
(loads fully on a 16 GB GPU at that context size) together with the prompt template, which is small.
Methods over the threshold are never sent to the model. They still get a
line in `summaries.jsonl` with `too_long: true`, `check: "skipped"`, and
every other field empty - there is no label to show, only the fact that
this method needs a human or a different approach (e.g. splitting it
further, or just reading it directly).

## Resumability

On start, the script reads the target's existing `summaries.jsonl` and
builds a set of already-labeled `exported_file` names from it. Those are
skipped on the next run unless `--force` is passed.

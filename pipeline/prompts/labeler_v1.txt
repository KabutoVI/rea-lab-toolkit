You are labeling a single method from decompiled code, for a reverse-engineering index. You are not writing documentation and you are not being quoted verbatim anywhere except the evidence field below.

Read the method source given to you and respond with JSON matching the required schema. Do not include any text outside the JSON object.

Fields:
- guessed_name: your best guess at what this method's role is, as a short descriptive phrase (not necessarily its actual name).
- summary: one sentence describing what the method does.
- category: exactly one of: initialization, state, math, input, networking, rendering, ui, io, utility, other, unknown.
  - Use the category that best matches the method's primary purpose, not every API it happens to touch.
  - If you pass --categories to labeler.py, use a prompt that lists the same categories.
- calls: a list of other method, API, or type names this method's body calls or references (e.g. "Socket.Send", "Math.Sqrt"). Only list names that literally appear in the given source.
- confidence: low, medium, or high, reflecting how sure you are about guessed_name and category given the evidence available. Use "unknown" only if the method body gives essentially no signal either way.
- too_long: always false. You are only ever given methods that already fit in the context window; this field is filled in by the calling script for methods it decides not to send to you at all.
- evidence: an exact 1 to 2 line quote, copied character-for-character from the method source given to you, that most directly supports your summary and category. It must appear verbatim in the input. Do not paraphrase, reformat, or add/remove whitespace.

Respond with JSON only.
